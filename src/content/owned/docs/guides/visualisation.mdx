A visual view helps a team discuss a model without reading every YAML file. It makes model boundaries, embedded structures and shared identities easier to inspect together.

## Work visually in Studio

Studio already provides an editable model canvas. Add model kinds and fields, connect references and objects, inspect metadata, and arrange related models. Focus and field highlighting help inspect larger graphs.

The canvas shows reference repeatability at the destination using labels such as `0..1` or `0..*`. These describe how many values the field permits; they do not describe how many other models may reference the target.

Save a workspace backup to preserve positions and layout. Export CMMF models when you need portable YAML. [Read Studio’s file and storage boundaries](/tools/#studio).

## Generate a review diagram

The Skills development tools can generate Markdown catalogues and Mermaid relationship diagrams from a validated model graph. Keep the diagram source in Git with the model set when a review needs a stable record.

A useful relationship view distinguishes:

- `object` embedding from `reference` linking;
- independent identity from ownership intent;
- singular values from repeatable fields;
- all five model kinds;
- required fields from optional fields in detailed views.

Always explain the important relationships in text as well. A diagram should help a reader understand the model without relying on colour alone.

## Keep presentation separate from meaning

Studio positions, generated routes and visual grouping are presentation data. CMMF YAML exports keep them separate from the portable model definitions.

FigJam/Miro board exports are prospective capabilities in the supplied planning material. The current tool snapshots do not establish an implemented board exporter or hosted collaborative editor.


## Download a relationship diagram

The complete example sets also have static SVG diagrams generated from their model files during the site build. They include rich-text reference edges and have text descriptions. The same graph is available as Mermaid source for use in other documentation.
